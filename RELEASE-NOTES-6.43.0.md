## Decisions taken

The design (research/v7/holdings-and-move.md §9) ruled on eleven points; these are the ones taken beyond it while building, each
the owner can overturn.

1. **A typed edit keeps a pasted record marked as pasted.** §1 says `source` is 'typed' after a typed change; the planner's own
   handler keeps 'paste' (or 'imported') on an edit or an add and sets 'typed' only on a record that was typed. The lifted
   function keeps the planner's rule, so the planner's behaviour is unchanged and both apps write the same record; a Remove
   keeps the source as it was. (`HoldingsRecord.holdingsWith`; the gate pins it.)
2. **The stamp is the one write file's, not the patch's.** §6 writes `holdPatch → { patch: { holdings, lastModified } }`; every
   other patch in V7 leaves `lastModified` to planWrite.js (one stamp, one place), and the hold and move patches do the same.
   `HOLD_WRITES` and `MOVE_WRITES` still name it, as §2.2 and §3.8 say; `ALL_WRITES` keeps the stamp last.
3. **The mix as held is read from the pension's lines.** §3.3 says "proportions of the record"; the four amounts the engine
   starts from describe the pension pot, and an ISA line is the engine's own separate pool, so the held mix is the record's
   pension lines in proportion on the same pot (every line when there is no pension line). The screen says "in your pension".
4. **The order sheet shows the price at lock, not the index ratio.** The planner's sheet prints the index ratio to three
   places; the words rule (banned.js odd-decimals) forbids a figure with three decimals on a plan page, and the cost at lock
   already carries it. The clean price (two places) and the cost are shown; `orderSheetRows` still carries `indexRatio` for
   the planner's own HTML.
5. **Five state files, not nine.** §7 names nine states; the four 03/04/05 plans pretty-printed with their readings came to
   1.1 MB. The builder now leaves the reading (`plans.view`) out of the hold and move states — it is the plan source's, recomputed
   on load, and the render tests refresh it through `viewFor` as the app does — and writes five files (hold-empty, hold-typed,
   hold-paste, move-ladder, move-mix: 296 KB in all); hold-locked, move-saver, move-notLocked and move-done are made from
   those in the render tests by the reducer (a route change, the fixture's own record put back). `inPinnedShape` now keeps a
   state slice the reference state predates (`move`), so `--only` writes the new slice.
6. **The hand-over place `rotation` names its strategy page.** `OpenPlace.PLACES` entries gained an optional `page`; the planner's
   OpenPlace module opens that strategy page (the ladder + rotation) instead of the overview when a place names one.
7. **`PlanReading.moveInputs` also returns `runUpMonthly` and `strategyParams`** (two extra keys), so the order sheet's
   "bought" marks are read against the same target the move reads.
8. **The equity file is fetched at `../data/equity.json`.** §3.7 says "./data/equity.json as the planner does": the planner's
   path is relative to its own page at the site root; from /v7/ the same file is one level up.
9. **`splitLadderAtAge` lives in `RotationStatus.js`** (re-exported under its old name from `GiltRotation.js`), so the move's
   reading reaches the rotation's block without the engine (the boundary test now pins that `move.js` reaches neither
   `GiltRotation.js`, `ladderEngine.js` nor the market history).
10. **`_made-with.json` is not rewritten** (the builder writes it only on a whole run); the hold and move render tests check the
    version and the futures it records, not its list of runs.
